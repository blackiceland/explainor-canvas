# Visual Language — Explainor Canvas

Свод правил, констант и паттернов визуального языка проекта.
Используется LLM перед сборкой любой новой сцены и автором — как чек-лист.

> Перед написанием новой сцены: прочитать раздел «Визуальный почерк» ниже →
> пройтись по разделам 1–8 → найти ближайший эталон в разделе 13 → читать
> его исходник целиком → сверяться с разделом 10 (анти-паттерны).

Все цитаты — `file:line` относительно `motion-canvas/src/`.
Раздел 12 — внутренние противоречия, которые ждут решения.

## Визуальный почерк

Короткая характеристика канала: **тёмный студийный минимализм, низкая
плотность кадра, много воздуха, статичная центрированная композиция,
дисциплинированная трёхакцентная палитра, спокойная двухгарнитурная
типографика, мягкая медленная анимация на одной кривой, код как главный
субъект сцены без рамок и подложек, ограниченный словарь геометрических
метафор, низкий драматизм с кульминациями-аккордами**.

Развёрнуто по осям:

**Темп** — медленный, инженерный, продиктованный мыслью, а не лентой.
После вопроса в центре кадра — пауза 1.4–2 секунды, чтобы зритель успел
сформулировать свою версию ответа; после появления нового кода — 2 секунды
холда под закадровый голос; между смысловыми битами внутри сцены —
0.3–0.8 секунды дыхания. Финал — короткий хвост в 0.3 секунды перед
склейкой, без агрессивных кат-аутов. Никакого ускорения ради динамики,
никаких быстрых нарезок.

**Плотность кадра** — низкая. На экране одновременно живёт ровно столько
элементов, сколько нужно для текущей мысли: либо один центральный объект
(вопрос, цитата, блок кода), либо чёткий сплит из двух уровней — код
слева, визуализация справа. Большие поля воздуха вокруг главного элемента:
рабочая область 1680×960 на канвасе 1920×1080 с 80–120-пиксельной
сейф-зоной от краёв. Вспомогательная визуализация — это всегда **полная
геометрическая метафора** (граф зависимостей, мембрана, треугольник,
орбита), не декоративный оверлей из чипов и стрелок.

**Настроение** — сдержанное, ночное, инженерное. Не «холодно-
технологичное» и не «корпоративное», скорее как тёмный лабораторный
блокнот при настольной лампе: графитовый фон, едва тёплый спотлайт
сверху-слева, ничего блестящего, ничего пёстрого. Сквозит уважение к
зрителю — ему доверяют дочитать кадр без подсказок и успеть подумать без
подгона. Без иронии, без пафоса, без эмодзи.

**Композиция** — статичная, центрированная, симметричная. Главный объект
— точно в центре или на одной из двух вертикальных осей сплит-разметки.
Сплит чёткий, без декоративных разделителей. Сцены «герой + цитата +
атрибуция» строятся в три яруса по вертикали с шагом ≈200 пикселей. Нет
рваных диагональных композиций, нет коллажей. Когда добавляются
вспомогательные элементы, они расположены на регулярной невидимой сетке
от центрального объекта.

**Цветовая система** — дисциплинированная, трёхголосая. Фон —
вертикальный градиент `#0B0C10 → #12141A` с радиальным тёплым спотлайтом
из верхнего левого угла на 4.5% непрозрачности (едва-едва, чтобы фон не
казался плоским). Текст по умолчанию — кремовый `#F4F1EB`,
второстепенный — тот же кремовый при 72%, затухший — 30%. Палитра кода:
ключевые слова — холодный голубой, типы — пыльно-лавандовый, методы —
розовый, переменные — яркий кремовый, строки — мягкий зелёный. Акцентов
в кадре всего три: **розовый `#FF8CA3`** — тревога, эмфаз, ключевые
имена методов; **холодный голубой** — правильные границы, мембраны,
треугольные рёбра; **оранжево-красный** — нарушения и чужая
ответственность. Больше ничего: ни жёлтого, ни лайма, ни фиолетового.
Кадр читается как чёрно-белая страница с тремя смысловыми вспышками.

**Типографика** — спокойная, ролевая, с чёткой иерархией. Проза — Space
Grotesk (с падением на Inter): вопросы 50–54pt вес 500, заголовки глав
140pt вес 500 с подтянутым межбуквенным трекингом −3, подзаголовки 40pt,
captions 24pt вес 300, эпиграфические подписи 22pt вес 700 ALL CAPS с
трекингом 3. Код — JetBrains Mono (с падением на IBM Plex Mono): кодовые
блоки 22–52pt в зависимости от плотности кадра, line-height просторный
(fontSize × 1.62), без курсивов и без декоративных весов внутри кода.
Цитаты подаются как машинописный набор: монохромная 44pt в JetBrains
Mono с естественными паузами на знаках препинания, атрибуция — Space
Grotesk 42pt в розовом акценте. Никаких обводок, теней под текстом и
эффектов glow вокруг букв.

**Движение** — мягкое, редкое, в одном характере. Базовая кривая —
`easeInOutCubic` на 95% твинов; `easeOutCubic` для мягких приземлений
(рёбра треугольника, мембрана), `easeInCubic` для уходов с ускорением,
`easeInQuad` — один раз на главу для драматического разгона. Ничего не
выскакивает: всё проявляется через opacity и плавное смещение, без
bounce, без spring, без эффектов «pop»-масштабирования. Длительности
кучкуются в три бакета: 0.3s — быстрая микро-смена, 0.6s — стандартный
переход, 1.1s — важный заход или уход. Скроллы кода и параллакс-движения
— без инерции, в том же спокойном характере.

**Работа с кодом** — главное визуальное отличие канала. Код **не
подложен под карточку**, не вписан в плашку с тенью — он парит на чистом
графите, удерживаемый только цветом токенов и кеглем шрифта. Подсветка
важных мест делается **через перекрашивание токенов**, а не через
подложки или плашки за кодом; никаких полупрозрачных подложек и
`showBackground` под кодом, никаких dim'ов остального кода ради фокуса.
Код **живёт во времени**: в течение сцены метод обрастает аргументами,
тело переписывается, появляются новые приватные методы, удалённые токены
коротко вспыхивают красным и стираются обратной печатной машинкой — это
семантические морфы, не cross-fade'ы. Когда нужно что-то подчеркнуть,
появляется тонкая полупрозрачная розовая полоса высотой в строку,
привязанная к её Y-координате, — она следует за скроллом. Когда нужно
очертить «зону внимания», вокруг блока строк прорисовывается тонкая
обводка кремового цвета без заливки.

**Метафоры** — геометрические, переиспользуемые, сдержанные. Вокруг кода
появляется ограниченный словарь вспомогательных форм: **чипы** —
маленькие закруглённые прямоугольники с короткой подписью (требование,
контекст, признак); **стрелки** — тонкие линии в 2–3 пикселя,
прорисовывающиеся от точки до точки за полсекунды через анимацию
end-сигнала, иногда с наконечником; **рамки** — тонкая обводка без
заливки вокруг важной зоны; **граф ответственности** — закруглённые
прямоугольники, соединённые ступенчатыми 4-точечными линиями без
диагоналей; **мембрана** — окружность с голубой обводкой и почти
прозрачной заливкой, удар по мембране показывается короткой вспышкой
обводки в оранжевый и возвратом; **треугольник-усилитель** — три
неоновые голубые ребра (двойная линия: толстый glow и тонкое ядро) с
подписями над апексом и под основанием; **орбита** — три блока кода,
медленно вращающиеся вокруг центрального слова на фоне проволочного 3D-
глобуса. Каждая метафора отрабатывает ровно один тезис и уходит из кадра
— нет фоновых декораций, висящих между сценами.

**Уровень драматизма** — низкий по базовой ткани, но с **точечными
кульминациями**. Основной материал видео — спокойное движение и долгие
холды; никаких звуковых стингов внутри визуала, никаких быстрых
монтажных нарезок, никаких пульсирующих эффектов и flash-кадров.
Кульминация делается **аккордом**: после нескольких последовательных
шагов (один чип, потом второй, потом третий) несколько элементов
одновременно зажигаются в `all(...)` — три ребра треугольника, три
стрелки давления, три места изменения в коде. После длинной выдержки
этот одновременный «взрыв» читается как сильный смысловой удар, при том
что он визуально мягкий: просто параллельные fade-in'ы за 0.5 секунды,
без музыкального стинга и без резкого света. Драма строится контрастом
между долгими паузами и аккордами, а не агрессией движения.

## 2. Палитра

### 2.1 Фон сцены

**Источник:** `core/theme.ts:1-14`, `core/utils.tsx:36-93`.

Фон формируется функцией `applyBackground(view)` — это **первый вызов**
любой сцены. Внутри:

- Вертикальный градиент `#0B0C10 → #12141A` (поднятый графит, не чистый
  чёрный — на телефонах с auto-brightness читается без перекрутки яркости).
- Радиальный спотлайт сверху-слева `rgba(246,231,212,0.045) → transparent`
  — едва заметная тёплая подсветка, оживляет кадр, не подсвечивает карточки.

**Why:** чистый чёрный `#000` смотрится плоско и режет глаза на мобильных
дисплеях. Поднятый графит + тёплый спотлайт даёт «студийную» глубину без
визуального шума.

| Переменная             | Значение            | Роль                         |
|------------------------|---------------------|------------------------------|
| `Colors.background.from` | `#0B0C10`         | Верх вертикального градиента |
| `Colors.background.to`   | `#12141A`         | Низ                          |
| `Colors.surface`         | `#1B1D21`         | Тёмные карточки/панели       |

### 2.3 Акцент

`Colors.accent = '#FF8CA3'` — единственный розовый акцент. Используется
для:
- атрибуций цитат (`prematureAbstractionQuoteSceneEn.tsx:51-61`),
- цвета методов в подсветке кода (`theme.method`),
- эмфаза внутри цитаты (`correctBoundariesSceneRu.tsx:84`).

**Why:** один акцент = один смысл. Если появляется второй акцентный цвет,
зритель теряет систему координат.

вручную правилом `{match: /^User$/, color: TYPE_CLEAN}`.

**Эталон:** `codeWithActionsSceneRu.config.ts:36-79` — образцовый набор
`COLOR_RULES` для пайплайн-сцен.

### 3.3 Жёсткие правила

- **Code lineHeight = `Math.round(fontSize * 1.62 * 10) / 10`.** Проектная
  константа, перекрывает дефолт 1.5 из `TextMeasure.ts`. Используется в
  100% code-сцен. **Why:** более просторный код легче читается на 1080p.
- **`fontWeight: 700`** — только для хайра «эйброу-номера» и центрального
  слова-якоря. Не для заголовков (там 500).
- **`fontWeight: 300`** — мягкие captions под заголовком/цитатой.
- **`fontWeight: 600`** — встроенный акцент внутри `300`-тонкой цитаты
  (`<Txt fill={accent} fontWeight={600}>...</Txt>`).
- **letterSpacing -3** для героя 140pt (стянуть в дисплейный размер).
- **letterSpacing 2-3** для коротких всё-капсом подписей.
- **Точка в конце короткого hero-заголовка** — стилевой акцент
  («Premature abstraction.»).

## 5. Тайминг и ритм

### 5.1 Канонические бакеты

**Источник:** `core/theme.ts:26-32`.

```ts
Timing.micro  = 0.08   // micro-flicker
Timing.beat   = 0.22   // ритмический пульс
Timing.fast   = 0.30   // быстрый fade
Timing.normal = 0.60   // дефолт для большинства tweens
Timing.slow   = 1.10   // важный заход/уход
```

**Правило:** где значение совпадает с бакетом — использовать константу.
Где намеренно отличается (0.5, 0.8) — оставить inline.

### 5.2 Бакеты на практике

**Fast (<0.5s):** микро-перекрашивание, dimLines, single-line emphasis,
short fade-out для подзаголовков.

**Medium (0.5–1.5s):** базовый язык переходов. `Timing.normal=0.6` —
дефолт. `0.8-1.1` — большие смены кадра (split-screen фокус-свитч,
membrane shrink, panel collapse).

**Slow (>2s):** холды смысла. `2.0-2.5s` — после ключевой реплики
сценария. `3.5s` — медленный rewind-скролл всего кода в финале.

### 5.3 Имитация чтения

- **Question hold:** появление 0.9s → hold 1.4s → уход 0.8s
  (`whyItIsAProblemSceneEn.tsx:31-49`).
- **Subtitle line:** in 0.5s → hold 1.4s → out 0.7s
  (`smallMethodsProblemsSubtitlesSceneRu.tsx:38-40`).
- **После появления кода / новой смысловой группы:** `waitFor(2)` под
  закадровый голос (`notifyPassThroughSceneRu.tsx:73,89`).
- **Между битами внутри сцены:** `waitFor(0.3-0.8)` — «дыхание».

### 5.4 Easing — когда что

- **`easeInOutCubic` — дефолт.** Любая opacity, position, color tween,
  если нет специфической причины. ~95% твинов.
- **`easeOutCubic`** — мягкое приземление: триангл-ребра в финале фазы,
  membrane появляется, three-up bullets втекают.
- **`easeInCubic`** — ускоряющийся уход (outro, исчезающие элементы).
- **`easeInQuad`** — драматический разгон (один раз: guitar-hero scroll,
  `codeWithActionsSceneRuTilt.tsx:310`).
- **`linear`** — sweep/paint progress на пайплайн-панели
  (`codeWithActionsSceneRu.tsx:135`).

### 5.5 Typewriter delays для цитат

**Источник:** `prematureAbstractionQuoteSceneEn.tsx:69-78`.
```
'\n'                  → 0.22s   (паузы между строками)
' '                   → 0.035s
".":";:!?—–"          → 0.09s   (знаки препинания — длиннее, для дыхания)
default char          → 0.032s
```

Манентикорный typewriter (`Manticore.ts:502-504`): `charDelay = 0.012`,
`lineDelay = 0.03`; punctuation × 1.5, space × 0.5, tab × 0.3.

### 5.6 Финал сцены

```ts
yield* all( /* всё → opacity(0) на Timing.slow или 0.8 */ );
yield* waitFor(0.3); // короткий хвост перед склейкой
```

## 6. Рендеринг кода — Manticore

### 6.1 Обязательный `cardStyle` — прозрачная карточка

**Why:** код «парит» на градиентном фоне; никаких опаковых подложек
(см. правило 7 в разделе 10).

```ts
const CODE_CARD_STYLE = {
  radius: 24,                        // 16 в орбит-сцене с 3D
  fill: 'rgba(0,0,0,0)',
  stroke: 'rgba(0,0,0,0)',
  strokeWidth: 0,
  shadowColor: 'rgba(0,0,0,0)',
  shadowBlur: 0, shadowOffsetX: 0, shadowOffsetY: 0,
  edge: false,
} as const;
```

**Эталон:** `codeWithActionsSceneRu.config.ts:42-46`.

### 6.2 Конвенции `Manticore.create`

```ts
const fontSize   = 22;
const lineHeight = Math.round(fontSize * 1.62 * 10) / 10;
const topInset   = Math.max(8, getCodePaddingY(fontSize) - 8);

const cb = Manticore.create(code, {
  x: LEFT_CENTER_X - 50, y: -50,           // эмпирические оффсеты, см. 6.5
  width: CODE_W,
  height: SafeZone.bottom - SafeZone.top - 36,
  fontSize, lineHeight,
  contentOffsetY: topInset,
  fontFamily: Fonts.code,
  theme: DryFiltersV3CodeTheme,
  cardStyle: CODE_CARD_STYLE,
  glowAccent: false,                       // ← всегда false (см. 6.3)
  customTypes: ['User', 'String', /* ... */],
});
cb.mount(view);
cb.colorize(COLOR_RULES);
yield* cb.appear(Timing.slow);
```

### 6.3 Жёсткие правила

- **`glowAccent: false` всегда.** API-дефолт `true`, но в продакшене — нет.
- **`cardStyle` всегда полностью прозрачный.** Радиус: 24 для пайплайн-
  сцен, 16 для орбит-сцены с globe.
- **`customTypes` всегда заполнен** всеми проектными типами. Решает две
  проблемы: коллизия `type/constant` + правильное распознавание метод-
  вызовов.
- **`contentOffsetY: topInset`** — центрирует код внутри клип-области.
- **`noClip: true`** — только когда код принципиально не должен
  обрезаться (орбита, parallax). Для скроллинга — стандарт (clip on).

### 6.4 `ColorRule` — правила раскраски

```ts
{match: string | RegExp, color: string, onlyTypes?: TokenType[]}
```

- **Plain string** → matches token text, включая подстроки:
  `{match: 'cube', color: VAR_LIGHT}`.
- **Anchored regex** → exact match: `{match: /^public$/, color: KW_COLOR}`.
- **`onlyTypes`** → ограничить применение конкретными типами токенов:
  `{match: 'grab', color: METHOD_COLOR, onlyTypes: ['method']}` — чтобы
  имя метода не подкрашивалось как переменная или тип.

**Порядок:** **LAST match wins.** Широкие правила сверху, узкие override —
снизу. Это критично для green-typing (см. раздел 7.4).

**Эталон:** `codeWithActionsSceneRu.config.ts:48-79`,
`grabStrategyOrbitSceneEn.tsx:54-75`.

### 6.5 Эмпирический Y-shift bug

**Источник:** `refactoring.md:240-334`.

Формула `cfg.y - ((N-1)/2)*lineHeight` промахивается ~250–270px от
реальной позиции первой строки. Сейчас все сцены подбирают `y`
эмпирически — для full-height блока это `y: -50`. **Не пересчитывать
формулой, копировать рабочее значение из эталонной сцены.**

### 6.6 Когда сырая строка vs JavaClass

- **Сырая строка** — код фиксирован для всей сцены (`notifyPassThrough`,
  `grabStrategyOrbit`, `chapterTwoOpenSceneEn`).
- **JavaClass model** — код мутирует во время сцены через Medusa-edit'ы
  (`codeWithActionsSceneRu`, `correctBoundariesSceneRu`).

### 6.7 Mount → colorize → appear

```ts
const cb = Manticore.create(code, {...});
cb.mount(view);
cb.colorize(COLOR_RULES);
cb.node.opacity(1);              // или yield* cb.appear(Timing.slow);
```

Декларативный `colorize(COLOR_RULES)` — канон. Старый паттерн
`code.recolorTokens(i, [...], color, 0)` line-by-line — legacy.

## 7. Code morph — JavaClass + Medusa

**Источник:** `feedback_code_morph_style.md`, `Medusa.ts`,
`MorphProfiles.ts`. Канон: `codeWithActionsSceneRu.tsx`,
`correctBoundariesSceneRu.tsx`.

### 7.1 Базовая сборка

```ts
import {JavaClass, method, param} from '../core/code/model/JavaModel';
import {Medusa} from '../core/code/director/Medusa';

const model = JavaClass.create([
  method('public', 'byte[]', 'exportVideo',
    [param('byte[]', 'sourceFrames')],
    ['validateInput(sourceFrames);',
     'return runEncoder(sourceFrames);']),
], MAX_LINE_CHARS);

const cb = Manticore.create(model.render(), {...});
cb.mount(view);
cb.colorize(COLOR_RULES);

const dir = new Medusa(model, cb, {
  morphDefaults: {scrollStrategy: 'block', removeDuration: 0, moveDuration: 0.6},
  pauseAfterMorph: 0.5,
});
```

### 7.2 Семантические эдиты

Все правки — через директора, не напрямую через `mc.morphTo`:

| API                                              | Что делает                                               |
|--------------------------------------------------|----------------------------------------------------------|
| `dir.addParam(name, param('T', 'x'))`            | Добавить параметр; авто-скролл к методу                  |
| `dir.setBody(name, [...lines])`                  | Полная замена тела                                       |
| `dir.replaceLine(name, oldLine, ...newLines)`    | Заменить одну строку (или развернуть в несколько)        |
| `dir.updateCallArgs(name, callName, [...args])`  | Обновить аргументы вызова внутри метода                  |
| `dir.addMethod(m, afterMethodName)`              | Новый метод (typewriter-стиль)                           |
| `dir.addMethodFade(m, afterMethodName)`          | Новый метод (fade-стиль) — когда нужно быстрее           |
| `dir.scrollTo(target, duration)`                 | Скролл к строке/методу                                   |
| `dir.apply(m => { m.replaceLine(...); m.updateCallArgs(...); }, {profile})` | Несколько эдитов в одном морфе |

### 7.3 Морф-профили

**Источник:** `MorphProfiles.ts`.

- `stableExpand` — дефолт; `scrollStrategy: 'block'`, `removeDuration: 0`,
  `moveDuration: 0.6`. Расширение существующих структур.
- `methodAdd` — `scrollStrategy: 'auto'`, typewriter add: `lineDelay: 0.03`,
  `charDelay: 0.012`.
- `methodAddFade` — те же таймы, но `addStyle: 'fade'` вместо typewriter.
  Когда новый метод большой и не хочется растягивать ритм.
- `argSwap` — флэш удалённых токенов в `rgba(255,80,80,0.95)` за 0.2s,
  потом стирание `reverseType`-typewriter'ом. Узко для замен аргументов
  типа `runEncoder` → `encodeWithRetry` (`codeWithActionsSceneRu.tsx:229`).

### 7.4 Green typing новых объектов

**Источник:** `feedback_green_typing_new_objects.md`.

Когда в аргумент метода добавляется ссылка на свежесозданный объект
(`arm.confirmGrip(confidence)` → `arm.confirmGrip(result.confidence)`),
новые токены печатаются **зелёным** и затем перекрашиваются в
нормальные цвета.

```ts
const GREEN_RULES = [
  ...NORMAL_RULES,
  {match: 'result', color: SOFT_GREEN},          // конкретный новый идентификатор
  {match: 'confidence', color: SOFT_GREEN},
];
mc.colorize(GREEN_RULES);
yield* mc.morphTo(model.render(), {addStyle: 'fade'});
yield* mc.colorizeAnimated(0, lineCount-1, 0.6, NORMAL_RULES);
mc.colorize(NORMAL_RULES);                       // обновить внутренние правила
```

**Не применять для:** ключевых слов, типов, объявлений переменных,
`new X()`-цепочек. Только конкретный кейс — ссылка на свежий объект в
аргументе.

### 7.5 Cross-fade двух Manticore — исключение

В общем случае **запрещено** (см. раздел 10). Единственный канонический
кейс: финальная драматическая смена «образца» в
`codeWithActionsSceneRuTilt.tsx:144-194`, когда старая модель
сменяется новой как «другой биологический вид». Не использовать для
обычных морфов.

## 8. Моушен-примитивы

> **Критично:** перечисленные примитивы — это **части конкретных
> метафор**, в которых они появляются, а не универсальный декоративный
> словарь, который можно сыпать вокруг кода. Stripe живёт за строкой
> кода. Tree-box — узел в графе зависимостей. Arrow с end-сигналом —
> ветка decision-диаграммы или удар в мембрану. Triangle, Membrane,
> Diamond — каждая полная метафора, центр своей сцены.
>
> **Чего категорически НЕТ в каноне:**
> - Капсул-таблеток с короткой подписью, плавающих вокруг кода
>   («requirement-чипы», «context-чипы»).
> - Пунктирных декоративных коннекторов между плавающими элементами.
> - Стрелок, указывающих от внешних элементов на конкретные строки
>   кода.
> - Мелких каптион-подписей под кодовыми панелями («thin working
>   path», «local form» и т. п.).
>
> Когда хочется показать «давление реальности» / «связи в системе» —
> используется одна из канонических метафор целиком (граф из tree-box
> + conn4, мембрана, треугольник, орбита) **или** подсветка происходит
> **внутри кода** (token-glow, token-recolor, stripe). Не оверлей.

### 8.1 Stripe — подсветка строки

**Эталон:** `codeWithActionsSceneRu.tsx:278-296`.

```ts
const STRIPE_COLOR = 'rgba(255,80,120,0.18)';
const stripeW = CODE_W + 40;
const stripeH = lineHeight * 1.15;
const stripeX = -Screen.width / 2 + stripeW / 2;

const stripe = new Rect({
  width: stripeW, height: stripeH,
  x: stripeX,
  y: cb.getLineSceneY(targetLineIdx),       // ← привязано к строке!
  fill: STRIPE_COLOR, opacity: 0, radius: 4,
});
view.add(stripe);
yield* stripe.opacity(1, 0.5, easeInOutCubic);
```

Полоса **широкая** (за пределами кода), **полупрозрачная** (`alpha 0.18`),
**закруглённая** (`radius 4`), **высотой `lineHeight × 1.15`**, **тянется
с кодом через `getLineSceneY`**. Для тревожной строки или транзитного
участка.

### 8.2 Tree-box — узел графа

### 8.4 Arrow с `end`-сигналом — только внутри метафоры

**Эталон:** `whyItIsAProblemSceneEn.tsx:248-262` — ветки decision-диаграммы
после ромба.

```ts
const arrow = createRef<Line>();
view.add(
  <Line ref={arrow}
    stroke={RULES_COLOR} lineWidth={3}
    points={[[fromX, fromY], [toX, toY]]}
    end={0}
    endArrow                            // если нужен наконечник
  />,

yield* arrow().end(1, 0.5, easeOutCubic);
```

Для multi-segment fork: `points=[[trunkX, forkY], [branchX, forkY],
[branchX, targetY]], radius=12, end=0`. Анимировать `end(1, 0.6,
easeOutCubic)` — линия «вырастает» от начала к концу.

**Где НЕЛЬЗЯ:** стрелка, указывающая от внешнего элемента на конкретную
строку кода. Это превращается в декоративный оверлей и нарушает канон.
Если нужна связь требования со строкой — это **stripe внутри кода**
(8.1) или **token-glow** (см. раздел 6.4).

### 8.5 Triangle с двойным glow

**Эталон:** `triangleAmplifierSceneRu.tsx:95-113`.

Каждое ребро — **две линии** одна поверх другой:
- glow: `stroke=GLOW_BLUE`, `lineWidth=10`, `opacity=0`
- core: `stroke=CORE_BLUE`, `lineWidth=2`, `opacity=0`

### 8.9 Three orbiting blocks

**Эталон:** `grabStrategyOrbitSceneEn.tsx:163-187`.

```ts
const PHASES = [-Math.PI/2, -Math.PI/2 + 2*Math.PI/3, -Math.PI/2 + 4*Math.PI/3];
const ORBIT_RX = 600, ORBIT_RY = 380, OMEGA = 0.20;

wrappers[i].x(() => Math.cos(phase + view.globalTime() * OMEGA) * ORBIT_RX);
wrappers[i].y(() => Math.sin(phase + view.globalTime() * OMEGA) * ORBIT_RY);
```

Через `view.globalTime()` — нет ручного yield-loop'а, поведение само
течёт. Для случая «несколько объектов вращаются вокруг центра без
сценарных событий».

## 9. Нарративные паттерны

### 9.1 Question → reveal

```ts
yield* questionTxt.opacity(1, 0.9, easeOutCubic);
yield* waitFor(1.4);
yield* questionTxt.opacity(0, 0.8, easeInOutCubic);
// затем строится сцена
```

**Эталон:** `whyItIsAProblemSceneEn.tsx:31-49`. Используется для входа
в главу: вопрос центром экрана 50–54pt, затем разворачивается
визуальный аргумент.

### 9.2 Multi-beat внутри сцены

Сцена делится на явные акты комментариями: `// ═══ Act 0 — opening
question ═══`, `// ═══ Point 1 — Boundary leakage ═══`. Внутри каждого
бита: показ → анимация → dim предыдущей буллет-точки → следующий бит.

**Эталон:** `whyItIsAProblemSceneEn.tsx:30,144,223,280,449`,
`correctBoundariesSceneRu.tsx:342,372,436`.

### 9.3 Three-way fork

Один источник → три ветки → симультанный пульс. Каждая ветка — `Line`
с `end=0` → `end(1, 0.5, easeOutCubic)`. В кульминации — симультанный
пульс целевых элементов в `all(...)`.

**Эталон:** `whyItIsAProblemSceneEn.tsx:280-447`.

### 9.4 Цитата — два варианта

**Открытие главы (typewriter):**
1. Hero title 140pt fades in (1.3s).
2. `waitFor(0.8)`.
3. Typewriter quote `Fonts.code` 44pt с custom char-delays.
4. `waitFor(0.5)`.
5. Attribution `Fonts.primary` 42pt accent fades in (0.9s).
6. `waitFor(3.2)` — поглощение.
7. Triple `opacity(0)` outro `Timing.slow`.

**Эталон:** `prematureAbstractionQuoteSceneEn.tsx`.

**Внутри бита (static fade):** `Fonts.primary` 40pt 300-weight, с
`<Txt fill={accent} fontWeight={600}>...</Txt>` для эмфаза. Italic
attribution 24pt muted под цитатой.

**Эталон:** `correctBoundariesSceneRu.tsx:79-97`.

### 9.5 Subtitle parade

Массив слов на разнесённых позициях, fade in 0.5s → hold 1.4s →
коллективный fade out 0.7s. Без центрального объекта, без переходов
кроме per-word opacity. Фон — `applyBackground` (не чёрный).

**Эталон:** `smallMethodsProblemsSubtitlesSceneRu.tsx`.

### 9.6 Аккорд в кульминации

**Принцип:** последовательные шаги строят напряжение, аккорд (всё в
`all(...)`) — выпуск. См. 4.6.

### 9.7 Переходы между битами

- **Major beat (новый смысловой блок):** fade everything out, brief
  `waitFor(0.3)`, build new.
- **Minor beat (внутри секции):** dim прошлый буллет до 0.3 alpha,
  bring next to 1.0, swap правую часть.

  shadowColor: 'rgba(0,0,0,0)', shadowBlur: 0, shadowOffsetX: 0, shadowOffsetY: 0,

    }

## 12. Открытые противоречия

Внутренние расхождения между правилами и кодом — нужно решить раз и
навсегда.

### 12.1 Чёрный фон vs `applyBackground`

Правило: всегда `applyBackground`. Но `globalStateSingletonSceneRu.tsx:126`
и `contextObjectSceneRu.tsx:73` рендерят `<Rect fill='#121212'/>`.

**Гипотеза:** raw black — для сцен с собственной графической метафорой
(светлый круг-маска, сетка летящих полей), где градиент конфликтует с
композицией. Подтвердить или отменить.

### 12.2 `dimLines` для фокуса

Правило: «не затемнять другой код». Но `validateMonolithSceneRu.tsx`,
`correctBoundariesSceneRu.tsx`, `codeWithActionsSceneRu.tsx` все
используют `dimLines` массово.

**Гипотеза:** запрет — про **первичный показ** кода (никаких dim'ов
сразу при появлении). После появления — для подчёркивания фокуса
voiceover'а — допустимо. Подтвердить.

### 12.3 Cross-Manticore cross-fade

Правило: запрет. Но `codeWithActionsSceneRuTilt.tsx:144-194` делает
именно это. Tilt — это финальная сцена-кода-как-зрелище. Считать
исключением «драматический финал главы», не использовать для обычного
морфа.

### 12.4 `Code` (vanilla) vs `Manticore`

`globalStateSingletonSceneRu` и `contextObjectSceneRu` используют
`@motion-canvas/2d.Code` напрямую с `drawHooks`, не Manticore. Это
оправдано там, где нужны **per-token branching color decisions** на
основе позиции/контекста (split-screen с разными темами слева/справа,
или blur-over-fly).

**Правило:** Manticore по умолчанию. `Code` напрямую — только для
spatial-сцен где код **не статически расположен на полотне**, а
является элементом физической анимации (летит, размывается, расходится).

### 12.5 `Timing.*` vs inline literals

Правило не сформулировано. Текущий код смешан: где-то `Timing.normal`,
где-то inline `0.6`, где-то `0.5` (не совпадающее с бакетом). Предлагаемое
правило: совпадает с бакетом — использовать константу; иначе — inline
literal с комментарием почему.

### 12.6 lineHeight: 1.62 vs 1.5 vs 1.35

- Code: `fontSize × 1.62`.
- `TextMeasure.getLineHeight` дефолт: 1.5.
- `triangleAmplifierSceneRu` body: 1.35.

Правило для прозы: **1.35** для дисплейных «разбросанных» подписей
(triangle, big labels), **1.5** для естественной прозы, **1.62** для
кода (просторнее).
